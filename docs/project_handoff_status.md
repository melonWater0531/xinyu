# 项目已完成功能与当前状态说明

本文用于交接确认，按真实完成状态记录。项目已经完成主要感知、云台控制、声源定位、设备播报、前端产品页和 LLM 陪伴能力；会议纪要尚未实现为可交付功能。

## 1. 单人场景：人脸检测/追踪 + reCamera 云台跟随

- 已实现单人人脸检测、目标追踪、锁脸、丢脸保持、搜索和回中逻辑。
- 已加入 demo 稳定模式和控制遥测，演示目标从“严格居中”调整为“脸在画面内且画面稳定”。
- 自动化测试覆盖了部分控制链路和状态契约。
- 人工测试已通过，实际演示时基本稳定。

## 2. 多人/声源场景：ReSpeaker DOA 驱动 reCamera yaw 转动

- 已实现 ReSpeaker DOA/VAD 到 EventBus，再到 `main_phase3`、Orchestrator 和云台 yaw-only 控制的链路。
- `/control` 中多人页定位为声源定位和调试演示，不是完整会议录音页。
- 真实设备测试已通过：人说话时云台能快速朝声源方向转动，反应迅速。

## 3. 会议录音、语音转文字和会议纪要

- 后端已实现会议开始/停止、录音分段、ASR 队列、WhisperX/Whisper 或云端 ASR 接入，以及 `/home` 会议页的异步状态展示。
- 此前使用腾讯会议录音做语音转文字是可行的，说明 ASR 工程链路并非完全未接通。
- 当前 ReSpeaker 实时录音音质很差，录出来的人声经常听不清，导致真实会议语音转文字无法稳定验收。
- 由于无法把 ReSpeaker 接到 reCamera 或其他原生 Linux 设备上做对照测试，暂时无法确认根因是 ReSpeaker 录音本身、WSL 采样、设备索引、增益还是驱动配置。
- 会议纪要功能尚未实现为可交付功能，不能写成已完成。

## 4. 语音交互与 reCamera 扬声器播放

- 已实现 TTS 音频缓存、Node-RED audio bridge、reCamera 端 `aplay` 播放、播放状态查询和提醒播报设置。
- 状态字段已区分 `bridge_accepted` 和设备端实际播放结果，避免只看 bridge 接收就误判为播放完成。
- 真实 reCamera 扬声器可以出声；智谱 TTS 播放、测试音和自动提醒均已人工通过。

## 5. 手势识别

- 已接入 MediaPipe 手势识别，可以展示手势类别、置信度和稳定帧。
- 当前手势识别只作为展示功能，尚未接入云台控制、语音停止或其他业务链路。

## 6. 前端产品页 `/home`

- 已完成心屿五页产品形态：首页、陪伴、会议、记录、我的。
- 已接入实时状态、陪伴聊天、日记、周报、会议入口、语音入口和提醒设置。
- 接口、设备或云端 key 不可用时有本地 seed/fallback，页面不会空白。
- 产品展示页已完成；会议相关展示受真实录音质量限制，不能作为会议纪要已完成来交付。

## 7. LLM 前端能力

- 陪伴聊天、日记反思和周报已经实现并部署。
- DeepSeek 和智谱均可配置；无 key 或调用失败时走本地 fallback。
- 会议相关接口入口存在，但会议纪要功能尚未完成，不能作为已实现能力交付。

## 8. 情绪、专注、眼部指标和健康提醒

- 情绪、注意力、眼部疲劳指标已经接入，并在前端展示。
- 久坐、眼疲劳和会议状态提醒作为正式功能接入。
- 提醒类功能尚未经过充分长时间真实场景测试。

## 9. 硬件控制基础设施

- 已完成单控制平面：FastAPI 不直接控制硬件，UI Event 走 EventBus 到 `main_phase3`，再经 Orchestrator、SafetyLayer 和 Node-RED bridge 控制云台。
- 已有 session/lease、防并发、遥测和安全边界。
- 当前没有让 FastAPI 或前端直接绕过 `main_phase3` 操作硬件。

## 10. 总体状态

已完成或基本完成的主功能包括：单人人脸追踪和云台跟随、多人声源 DOA 云台转向、reCamera 扬声器播报、心屿 `/home` 产品页、LLM 聊天/日记/周报、手势识别展示、情绪/专注/眼部指标、健康提醒和统一硬件控制基础设施。

未稳定完成的部分主要是 ReSpeaker 实时会议录音转文字，以及基于真实会议转写结果的会议纪要。这里的原因不是 ASR 工程链路完全没有接入，而是当前真实录音输入质量不可用；外部录音转写可行，但真实设备会议录音尚未达到稳定验收标准。
